## Summary
- Fixed the red test suite issue in `RootHandlerTest` (due to `Method i in android.util.Log not mocked`) by removing direct `android.util.Log` calls in `RootHandler` and delegating to injected `log: (String) -> Unit = {}`.
- Added `"root.disable"` to `RootHandler.METHODS`.
- Implemented `root.disable` in `RootHandler`: sets `rootManager.setEnabled(false)`, executes the injected `onDisabled` callback wrapped in `runCatching` (logging any error without failing the reply), and replies with the current `status()`. It is idempotent and never executes `su`.
- Reduced `root.status` logging in `RootHandler` to only emit when status (`available`, `granted`, `enabled`) changes from the previous logged state.
- Updated `docs/bridge-contract.md`:
  - `root.status` and `root.request` updated from `planned (Task 17)` to `live (Task 17)`.
  - Added table row for `root.disable` (`{}` → `{ available, granted, enabled }` | `live (Task 17)` | "Clears the preference, ends root sessions and jobs, never prompts").
  - Added `root.disable` to the Fast (10 s) timeout table.
  - Updated `root.lost` in the events table with `{ sessionId?, jobId?, reason }` and descriptive explanation of `"denied"` vs `"revoked"`.
- Verified generated types: `generateBridgeTypes` ran and confirmed 0 diff against `web/src/bridge/types.gen.ts`.
- Added unit tests in `RootHandlerTest` for `root.disable` disabling prefs, calling `onDisabled` once, running zero shell commands, idempotent invocations, error handling when `onDisabled` throws, `root.status` invoking no shell commands, and status deduplicated logging.

## Tests added
- `root disable with prefs enabled disables prefs calls hook and runs no shell commands`: Proves `root.disable` sets prefs enabled to false, invokes `onDisabled` once, returns `enabled=false, granted=false`, and invokes no shell commands.
- `root disable twice calls onDisabled twice without exception`: Proves idempotent invocations do not fail and call `onDisabled` on each invocation without errors.
- `root disable when onDisabled throws still succeeds and logs error`: Proves that an exception thrown by `onDisabled` is caught, logged via `log`, and does not cause `root.disable` to fail.
- `root status with prefs enabled runs no shell commands`: Proves `root.status` reads status without invoking any shell commands.
- `root status logs only when status changes`: Proves status log is only emitted when `available`, `granted`, or `enabled` changes.
- `unknown method throws E_UNKNOWN_METHOD`: Proves unrecognised method calls fail with `E_UNKNOWN_METHOD`.
