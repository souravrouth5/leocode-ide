Network note
  The LAN has no direct internet: devices resolve names but TCP to PyPI times
  out, and only the authenticated proxy 192.168.34.181:8080 works. The host ran
  a local CONNECT proxy on 127.0.0.1:18080 and exposed it with
  `adb reverse tcp:18080 tcp:18080`; pip used `--proxy http://127.0.0.1:18080`
  and requests used `https_proxy`/`http_proxy`. This is test plumbing only; the
  app itself does not depend on a proxy. The proxy was flaky for large reads
  (PyPI simple pages), which is why the D1 request install output was cut off
  at the transport level even though the install completed (verified with
  `pip show`).
