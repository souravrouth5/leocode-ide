T28.2 In-app self-update rc1 -> rc2 (FAILED on rc1, fixed in rc2)
  FAIL  rc1's updater rejected its own download with E_INTEGRITY.
        Root cause: on API 28 `getPackageArchiveInfo()` only collects archive
        certificates when `GET_SIGNATURES` is in the flag mask; rc1 asked for
        `GET_SIGNING_CERTIFICATES` alone, so the archive signer set came back
        empty and the integrity check failed closed.
        Fix in rc2: request both flags and fall back to `PackageInfo.signatures`
        (regression test `UpdateInstallerFlagsTest`). rc2 was then installed
        over rc1 with `adb install -r` to continue the demo.

Notes and known issues
----------------------
* D1's "Open with" chooser: Android 9 shows a chooser when more than one
  installed app handles `application/vnd.android.package-archive`. Picking
  "Package installer" completes the update, so the row passes, but the extra
  step is a real UX difference from D2 (which opens the installer directly).
  A future task can move to `PackageInstaller` sessions, which never show a
  chooser.
* D1 Play Protect blocked the sideload once and needed "More details" ->
  "Install anyway"; D2 showed the softer "Scan app" dialog. This is Play
  Protect policy for an app Google has not seen, not an APK signature problem
  (Android's own update prompt already verified the signer matches).
* D1's WebView is Chrome 80 (`com.google.android.webview` 80.0.3987.99) and
  logs `Uncaught TypeError: Cannot read properties of null (reading 'style')`
  twice during startup. It is pre-existing (also present in the rc1 smoke log)
  and does not block the UI: the cold start passes and the app is usable.
  D2 logs no such error. Left as a follow-up; not introduced by Task 28.
* D1's download/resume row from the runtime matrix is N/A for transport reasons
  and was not toggled. Neither phone is rooted, so no Phase E rows were run.
